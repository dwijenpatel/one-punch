- `runcore.py` (533 lines) is the new pure core of the loop (see Deviations). It holds:
  - `parse_run_config`: the `[run]` table.
  - `fold_ledger`: every ticket's state from events.
  - `plan_round`: launch, park or stop. It also rejects any candidate that overlaps an in-flight ticket, using select_batch's pairwise rule.
  - Grammars: `decision_items`, `acceptance_commands`, `set_header`, `is_limit`, `failure_note`.
  - Preamble: `build_instructions`, `depends_rows`.
- **No state file.** State is ticket `Status:` at H, plus the `t/<t>` branches, plus the JSONL ledger, recomputed on every iteration.
  - A `launch` with no `worker-exit` counts as interrupted. On the next run its worktree is torn down, its branch is reset to the `start` sha recorded in the launch event, and the attempt is redone. Committed salvage from earlier attempts survives.
  - A clean exit that has no integrate event yet is integrated on restart.
  - A MERGED that has no Status flip (a crash, a hand-run `integrate.py`, or `--approve` between runs) is flipped on the next run. Tested.
- **Events and packets.** `events.jsonl` is committed. Every planner-direct commit, and every run stop, commits a snapshot of the on-disk ledger to the integration branch at `[run] ledger_snapshot` (default `.scratch/{effort}/ledger/events.jsonl`). This is a different path from the live file, so H3's merge of main never collides with the untracked working copy.
  - Readers fall back to the snapshot when the disk file is absent, as in a bare or fresh clone. Writers first seed the disk file from the snapshot.
  - Review packets stay on disk: they are regenerable, and AWAITING-OPERATOR is itself in the ledger.
- **Status flip.** After MERGED, `Status: done` is a planner-direct commit on `integrate/<effort>`. It uses plumbing: a temp index, `commit-tree`, and a CAS on `update-ref`, retried if the race is lost. The integration branch is never checked out. Also after MERGED: the worktree is removed and `t/<t>` is moved to the judged commit.
- **Outcomes** (all in `fold_ledger`):
  - AWAITING-OPERATOR: worktree removed; approve between runs.
  - FAILED, worker failure, HANDOFF-MISSING or NOTHING-TO-INTEGRATE: a failed attempt. The worktree is kept, and the retry runs one tier up via `core.route`, with a root-cause note built from integrate's check failures and verify tails. After 2 failures the ticket parks as `escalation`.
  - BLAST-ESCALATION: the raised level is committed to the ticket's `Blast:` line (planner-direct), and the work is retried in place. If the raise is to B3, the ticket parks as `blast-b3`.
  - CONFLICT: parks as `conflict`, for ticket 10's merge agent.
  - HEAD-MOVED: retried once, then parks.
  - HANDOFF-STATUS / BLOCKED / NEEDS_CONTEXT: parks as `blocked`.
  - INTEGRATION-BRANCH-CHECKED-OUT: transient; retried once the branch is switched away.
  - Other refusals: park as `refused`.
- **Stops** (in-flight workers drain first). Exit codes:
  - 0 FRONTIER-EMPTY
  - 3 ALL-PARKED
  - 4 DECISIONS-NEEDED (`park_k`, default 2)
  - 5 ALL-COOLING
  - 6 STOPPED (one SIGINT/SIGTERM, or the stop file `.worktrees/STOP`)
  - 7 KILLED (a second signal: every launcher's group gets SIGTERM, and the launches stay unmatched so the next run redoes them)
  - 30 REFUSED
  - 31 LOCKED
- **Usage governor.** A worker exit whose summary matches `limit_patterns` becomes a `LimitHit` (a `cooldown_s` cooldown). It is not a failed attempt, and it lowers N by 1 for the rest of the run.

Findings / concerns:
- `integrate_ticket` runs synchronously in the loop. While one ticket's verify runs, exits are not collected and slots are not refilled. Workers keep running, so nothing is lost, only refill latency. Integration is serial by design; if verify is slow, the optimization is to launch before integrating.
- A terminal ^C sends SIGINT to the whole foreground group, including integrate's git subprocesses, which are not session-isolated. Stop a background run with `kill -INT <pid>` or the stop file. Stopping from the planner session this way is safe.
- `mock.py` (ticket 11's Touches) does not forward SIGTERM, so a KILLED run under the mock orphans the scenario `sh`. The SIGINT test's slow scenario therefore only sleeps. `codex_p.py` has the same gap. Ticket 11 should copy claude_p's `Interrupted` handler into both.
