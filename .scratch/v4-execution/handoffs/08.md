- `plugin/skills/worker-harness/references/harness/integrate.py` is the imperative shell (753 lines). CLI: `integrate.py [--repo] [--config harness.toml] [--bundle DIR] TICKET`, plus `--approve TICKET`. API for 09: `integrate_ticket(repo, cfg, ticket, WorkerInfo)`, `approve_ticket(...)`, `writer_lock(repo)`, `load_config(path)`, `read_bundle(dir)`, `read_events(path)`. Sequence:
  1. Handoff check. The handoff is read from the ticket branch as committed (`<handoffs_dir>/<ticket>.md`). Its status must be DONE or DONE_WITH_CONCERNS, otherwise REFUSED.
  2. Refuse if the integration branch is checked out in any worktree.
  3. Read the ticket, the blast map and the ledger from the integration head H. They are never read from the ticket's own tree.
  4. `git worktree add --detach <tmp> t/NN`, then `rebase --no-update-refs H`. On conflict: abort, emit a CONFLICT event with `conflicted_paths`, and set `conflict_with` from a fold over the events (the last ticket to land each path).
  5. Run lint on H and on J (for the ratchet), then run verify on J. If verify modifies tracked files, the check fails with VERIFY-DIRTY.
  6. Run the checks.
  7. MERGED: `git update-ref <integ> J H` as a compare-and-swap. If the head moved, re-enter at step 3 (at most `max_reentries`, then HEAD-MOVED). `t/NN` is moved to J only when no worktree has it checked out.
  8. B3: pin J at `refs/one-punch/awaiting/NN`, write the packet to `<packets_dir>/NN/` (README.md, diff.patch, handoff, spec-verdict/lens/checklist answers, packet.json), and emit AWAITING-OPERATOR. `--approve` performs the same compare-and-swap against the packet's base. If the head has moved, approve deletes the stale pin and re-judges, which produces a fresh packet.
